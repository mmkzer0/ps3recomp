# SPEC-NOTES: defects, gaps and deviations found while implementing PROBE.md

PROBE.md itself is unchanged (hypotheses untouched). Evidence tiers: **PROVEN** = read in the spec or the PSL1GHT
sources at the pin, **INFERRED** = reasoning, **UNKNOWN** = needs the hardware.

## B. Choices that are not in the spec

- Run parameters come from `ring110.cfg` (USB stick root first, then `/dev_hdd0/tmp/hwprobe`) because an XMB launch has no arguments. No file = defaults of the layer. Every CSV records the effective values in `META`.
- On-screen status (hwprobe library): drawn only outside the timed section, never during it (README, measurement integrity rule); the screen can be switched off (`screen=0`), and every CSV records `ui_*` counters. Video output stays on during a run when the screen is on, so a run with `screen=0` is the control for its effect on the polling gaps. START begins and leaves a run unless `pad=0`; PS button "Quit Game" is honoured (the CSV of an aborted run is still written, `META,abort_reason,3`).
- Polling-thread priority: tries 0, 1, 2, 10, 100, 500, 1000 and logs the first that `sysThreadCreate` accepts (`META,poll_prio`). What lv2 grants a homebrew process is UNKNOWN.
- Layer 2 random extra delay (0..P) is applied after the quiet period, before waiting for the next index change. Because the next trial still starts on a tick, its only effect is to randomise which index `r` a trial lands on.
- Control C2 (markers in blocks 0 and 1 before `audioPortStart`) is `preset=c2`; C1 and C3 are presets `c1` and `c3` of the normal sweep.
- `analyze_layer2.py` uses the standard library only: no tool in this tree imports numpy and `requirements.txt` does not list it, so the tools tests (run by CI) must not need it. A marker is found as a burst of 3 to 8 consecutive 32-sample blocks whose peak is above the leading silence's noise threshold, then identified by normalised correlation (cosine, 0.5 or more, either channel) with the reference code, and for the rest with the codes of the trials whose reference arrives within reach. Two PN codes correlate at about 0.09 (1/sqrt(128)); the reference marker of a reference-only trial against four decoy codes is the reported false-alarm check.
- Joining to trials: the reference markers fix the clock map capture = c + s * timebase (offset and drift, robust fit; `s - 1` is the reported ppm); a marker m laps after a trial's reference is that trial's repeat. A capture that does not explain 70 % of the first 16 reference markers is refused (wrong WAV for the CSV) rather than fitted.
- PROBE.md §9 says to drop trials with a polling gap above 20 us near `t_c`. The campaign saw about 2.6 gaps per tick (median 33 us), so that would drop nearly everything. Only a gap logged at the same polling iteration as `t_c` makes `t_c` itself uncertain (the index change happened up to that gap earlier), so that is what removes a trial from the fit (`--max-tc-gap-ms`, default 20 us). Gaps elsewhere only delay the write, which `o_actual` already records.
- A marker whose correlation is below 0.8 of the reference markers' median is class `partial` (PROBE.md §9: "reject if peak < 0.8 of reference"), not hit or miss. A trial whose reference arrival plus the longest reply window lies beyond the end of the recording is `not_captured` and is left out of every count and fit, with a warning, so a cut-off file is reported and the rest is still usable (the trials are shuffled, so the missing ones do not bias the fit).
