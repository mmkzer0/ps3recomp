# Paths that may legitimately carry a hygiene finding, and why.
#
# One entry per line:
#
#     <glob> <rule-id> -- <reason>
#
# <glob> is matched with fnmatch() against the repository-relative POSIX
# path, so `dist/*.bin` also matches nested paths.  <rule-id> is one of
# forbidden-name, magic, oversize, symlink, deny-list.  The reason is mandatory: an
# allow-list entry without a written reason is how a leak becomes normal.
# An entry suppresses only its own rule for matching paths.
#
# An entry is for a file that was reviewed and is kept on purpose, such as a
# vendored third-party file with its licence and provenance beside it (a
# source.json naming the upstream commit and the file's sha256). Nothing else
# belongs here: a file that merely trips a rule is fixed or removed, not
# listed. Every other path must pass with no entry:
#
#     python3 tools/check_hygiene.py --tracked
